# Вебова інформаційна система для медичного центру

## Опис проекту

Цей проект є практичною частиною бакалаврської роботи на тему вебової інформаційної системи для медичного центру. Система призначена для базової організації роботи з пацієнтами, лікарями, візитами, спрощеною медичною документацією та доступом користувачів за ролями.

Проект демонструє взаємодію клієнтської частини, серверної частини та бази даних. Користувач працює з системою через браузер, React відповідає за інтерфейс, Express надає API, а MongoDB зберігає структуровані дані медичного центру.

## Основна функціональність

- вхід користувача за e-mail і паролем;
- автентифікація через JWT і захищені HTTP-cookie;
- розмежування доступу за ролями;
- перегляд, пошук, створення, редагування та архівування пацієнтів;
- перегляд лікарів, спеціалізацій і графіка роботи;
- створення, перегляд, скасування та завершення візитів;
- ведення спрощеної медичної документації;
- панель адміністратора для користувачів і ролей;
- системні логи для важливих дій;
- демонстраційні дані через seed-скрипт.

## Ролі користувачів

**Пацієнт** може переглядати власну картку, власні візити та власну медичну документацію.

**Лікар** бачить призначених пацієнтів, свої візити та медичні записи доступних йому пацієнтів. Лікар може створювати записи медичної документації.

**Реєстратор** керує базовими даними пацієнтів і візитами: додає пацієнтів, створює візити та змінює їхній статус.

**Адміністратор** керує користувачами, ролями, лікарями, пацієнтами та переглядає системні логи.

## Технології

- **React**: клієнтська частина вебової системи.
- **Bootstrap**: адаптивний і простий інтерфейс.
- **Node.js**: середовище виконання серверної частини.
- **Express**: REST API для роботи з даними.
- **MongoDB**: база даних для пацієнтів, користувачів, візитів і документації.
- **JWT**: автентифікація запитів користувача.
- **Bcrypt**: хешування паролів.

## Структура проекту

```text
backend/
  seed/                 seed-скрипт демонстраційної бази
  src/
    app.js              налаштування Express, CORS і маршрутів
    server.js           запуск API-сервера
    config/             змінні середовища і підключення MongoDB
    controllers/        логіка обробки API-запитів
    middlewares/        автентифікація, ролі, CSRF, санітизація, помилки
    models/             User, Patient, Appointment, MedicalRecord, AuditLog
    routes/             маршрути API
    scripts/            допоміжні seed-скрипти
    utils/              перевірка даних і контроль доступу
  test/                 інтеграційні тести API

frontend/
  src/
    components/         спільні компоненти інтерфейсу
    context/            контекст автентифікації і повідомлень
    layouts/            основний макет після входу
    pages/              сторінки системи
    services/           клієнт API
    utils/              підписи ролей і статусів
```

Лікарі зберігаються у моделі `User` з роллю `DOCTOR` і додатковими полями: спеціалізація, телефон, кабінет, опис і години роботи.

## Змінні середовища

Файл `backend/.env` створюється на основі `backend/.env.example`:

```env
PORT=5000
MONGO_URI=mongodb://localhost:27017/medical-center
JWT_SECRET=change_this_secret
JWT_EXPIRES_IN=8h
CLIENT_URL=http://localhost:3000
```

Файл `frontend/.env` створюється на основі `frontend/.env.example`:

```env
VITE_API_URL=http://localhost:5000/api
```

Файли `.env` не зберігаються в репозиторії. У них не можна залишати реальні паролі, секрети JWT або приватні рядки підключення до бази даних.

## Локальне встановлення і запуск

1. Клонувати репозиторій і перейти до папки проекту.

2. Встановити залежності backend:

```bash
cd backend
npm install
```

3. Створити файл середовища backend:

```bash
cp .env.example .env
```

4. Запустити локальний MongoDB або підготувати базу в MongoDB Atlas і вказати `MONGO_URI`.

5. Заповнити базу демонстраційними даними:

```bash
npm run seed
```

6. Запустити backend:

```bash
npm run dev
```

7. Встановити залежності frontend:

```bash
cd ../frontend
npm install
```

8. Створити файл середовища frontend:

```bash
cp .env.example .env
```

9. Запустити frontend:

```bash
npm run dev
```

10. Відкрити застосунок у браузері:

```text
http://localhost:3000
```

API за замовчуванням працює за адресою `http://localhost:5000/api`.

## Розгортання

Практичний варіант розгортання:

- база даних: MongoDB Atlas;
- backend: Render або Railway;
- frontend: Vercel або Netlify.

Для MongoDB Atlas потрібно створити кластер, базу даних, користувача бази та дозволити підключення з адреси хостингу backend. Рядок підключення додається до змінної `MONGO_URI` на Render або Railway.

Для backend на хостингу потрібно додати змінні:

```env
PORT=5000
MONGO_URI=mongodb+srv://...
JWT_SECRET=long_random_secret
JWT_EXPIRES_IN=8h
CLIENT_URL=https://your-frontend-domain.example
```

`CLIENT_URL` має збігатися з адресою frontend. Це потрібно для CORS, щоб браузер дозволив запити з клієнтської частини до API.

Для frontend потрібно додати:

```env
VITE_API_URL=https://your-backend-domain.example/api
```

Порядок розгортання:

1. Створити базу MongoDB Atlas і отримати `MONGO_URI`.
2. Розгорнути backend на Render або Railway.
3. Додати всі змінні середовища backend.
4. Переконатися, що endpoint `/api/health` повертає відповідь.
5. Розгорнути frontend на Vercel або Netlify.
6. Додати `VITE_API_URL` з адресою backend.
7. Оновити `CLIENT_URL` у backend відповідно до адреси frontend.
8. Перезапустити backend після зміни змінних.
9. Перевірити вхід, список пацієнтів, список лікарів, візити та панель адміністратора.

Seed у production-середовищі за замовчуванням заблокований. Якщо демонстраційні дані потрібні на тестовому сервері, потрібно запускати seed тільки для окремої тестової бази, яка не містить реальних даних.

## Нотатки з безпеки

- паролі зберігаються у вигляді Bcrypt-хешів;
- JWT використовується для автентифікованих запитів;
- доступ до маршрутів обмежується ролями користувача;
- backend додатково перевіряє доступ до даних пацієнта;
- секрети і рядки підключення зберігаються у змінних середовища;
- CORS налаштовується через `CLIENT_URL`;
- демонстраційні дані є вигаданими;
- це студентська система і вона не призначена для реального медичного використання без додаткової юридичної та технічної перевірки безпеки.
